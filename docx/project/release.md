# 源码整理与远程推送准备

## 交付原则

当前开发目录保留原样，不通过清理或重写Git历史掩盖开发过程。对外源码采用当前工作区文件的白名单快照，单独生成目录与ZIP，不复用旧Git历史。

原因是开发目录中保留了本地配置、运行备份和历史验收材料，旧Git记录还包含历史日志文件。即使当前 `.gitignore` 已忽略文件，也不能据此证明历史提交适合公开。发布按文件清单逐项暂存，不提交整个开发工作区。

## 可发布范围

- Java业务源码、Mapper、配置模板、JUnit测试与H2结构。
- Vue源码、依赖锁文件、单元/组件测试及隔离视觉样例。
- Python智能体、客户端、RAG、提示词、内置示例知识和自动测试。
- 数据库SQL、新装种子、启动/文档生成/源码导出脚本和部署样例。
- `docx/project` 当前文档集及公开版人工演示稿。

不包含：`.git`、本机配置/环境文件、target、node_modules、dist、私有data/索引、业务数据库与Redis备份、模型权重、云端凭据、历史日志、实际验收账号资料、临时调试与清库工具。开发者本机的既有HTTP夹具和历史验收脚本不视为可直接向任意数据库运行的公共脚本。

## 生成源码包

在项目根目录运行：

```powershell
python scripts/export-project-source.py
```

输出到 `target/project-delivery/` 的新目录和ZIP，包含文件SHA-256清单、文档链接检查及高置信密钥模式扫描结果，并与本机已配置的敏感值进行精确比对。检查不输出密钥值。`latest.json`记录最新产物位置。重复运行产生新目录，不递归删除已有材料。

接口更新流程：先执行 `ApiInventoryTests -Ddocs.export=true` 导出当前注册路由，再运行 `scripts/generate-api-docs.py`，检查生成结果后重新导出。OpenAPI中非泛型Result.data与开放Map保留开放类型，不伪造严格响应模型。

规则扫描不是绝对安全证明。公开前仍需人工检查知识资料、截图、测试数据、第三方许可证及模型外发说明。代码中的测试密码、测试签名密钥只用于隔离测试；正式部署必须使用自己的凭据并启用prod。

## 远程发布

目标仓库：https://github.com/yunf161/book-management

本次源码在独立的 `ai-library-release-20261021` 分支发布，原 `master` 的早期项目内容保留。发布分支从当前干净源码建立，不带本机开发目录的旧 Git 历史。

首次提交只包含 SOURCE-MANIFEST.json 中列出的源码、配置模板和正式说明，以及清单本身。本机配置、target、node_modules、dist、私有知识索引和历史调试材料均不提交。

推送前重新运行源码白名单导出检查，核对敏感值、文档链接和暂存文件范围。当前没有指定开源许可证；公开可见不等于授予任意复制、分发或商用授权。
